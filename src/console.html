What 2026 agent dashboards have in common

      
    
        
  • Conversation views of traces. LangSmith added a Messages View (May) and Trajectories (Sept). Built here as the Messages tab. LangChain
    • 
        
  • Failure clustering with suggested fixes. LangSmith Engine clusters production failures and opens PRs with fixes. Built here as Issues with "Draft fix with Claude". LangChain; a competitor criticised its lack of issue lifecycle
    • 
        
  • Two graph modes. Langfuse (July) shows an aggregated structure view and a per-run execution view. Built here as "This run / 24h traffic". Langfuse changelog
    • 
        
  • Service maps of agent → sub-agent → tool calls. Monte Carlo, Datadog and New Relic all added them in early 2026. vendor articles
    • 
        
  • Timelines that show parallel work. Langfuse's timeline and Honeycomb's agent swim lanes with a "failures only" filter. Built here as Lanes and the runs filter. Langfuse, Honeycomb
    • 
        
  • OpenTelemetry GenAI conventions are reported as stable in 2026, so traces move between tools. one vendor blog; unconfirmed
    • 
        
  • Trace-linked evals and datasets. Several tools turn failing traces into eval datasets. Built here as "Create eval dataset". Braintrust, Confident AI
    • 
        
  • Layout. LangGraph Studio keeps the thread picker compact and gives the graph the space; its docs place threads at the top of the right pane. LangChain docs

OpenTelemetry
The open standard that lets one agent trace show up in any of these dashboards.

    

      
OpenTelemetry (OTel) is an open-source, vendor-neutral standard for telemetry: traces, metrics and logs. It is a CNCF project with SDKs for Python, JS, Go, Java and more. Your code records what happened. An exporter ships that data over the OTLP protocol to whichever backend you pick. If you switch vendors, you change the exporter and leave your code alone.

      
For agents, the useful part is tracing. One run of the graph is a trace. Every node, model call and tool call inside it is a span with a start time, a duration, a parent and attributes. The GenAI semantic conventions standardize attribute names such as gen_ai.request.model and gen_ai.usage.input_tokens, so Langfuse, Phoenix, LangSmith or Datadog can all read cost and token usage the same way.

    

    

      
How data flows

→

Minimal Python span

        
from opentelemetry import trace

tracer = trace.get_tracer("refund_agent")

def researcher(state):
    with tracer.start_as_current_span("chat claude-sonnet-5-5") as span:
        span.set_attribute("gen_ai.operation.name", "chat")
        span.set_attribute("gen_ai.request.model", "claude-sonnet-5-5")
        resp = llm.invoke(state["messages"])
        usage = resp.usage_metadata
        span.set_attribute("gen_ai.usage.input_tokens", usage["input_tokens"])
        span.set_attribute("gen_ai.usage.output_tokens", usage["output_tokens"])
        return {"messages": [resp]}

      

      

        
Glossary

        

          
trace
One end-to-end run, such as a full graph invocation.

          
span
One timed step inside a trace. Spans nest into a tree.

          
attribute
A key/value fact on a span: model, tokens, tool name.

          
exporter
Sends spans out of your process, usually over OTLP.

          
collector
A standalone service that receives, filters and forwards telemetry.

          
context
The trace id carried across calls and services so spans join up.
