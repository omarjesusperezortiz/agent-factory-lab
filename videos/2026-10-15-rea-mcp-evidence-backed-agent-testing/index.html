REA: an agent that tests with evidence, not screenshots

Reverse Engineer Anything (REA) is an MCP server plus a skill that lets Claude Code or Codex follow a click down to the request it sends, save every request and response as evidence, and label each finding seen, guessed or unknown. Seven scenes: how it works, then the video's five use cases.

What this means for the factory

Idea from the videoWhat we do with it
Every capture gets an evidence ID; findings must cite oneAgent reports in Traces and the Human inbox carry an evidence ID or the label seen / guessed / unknown. A claim marked seen with no ID gets bounced back to the agent.
Black-box QA: "don't read the code, don't change anything"A separate QA agent tests the preview URL from the browser side only, against the spec and the home-page promises. It found the billing bug that a code review missed.
Write the behavior list before buildingWhen a ticket says "like app X", the first artifact is a behavior list (click, drag, delete). It becomes the acceptance test for the build agent.
Pre-launch sweep of what actually shipsBefore release, scan the bundle that reaches the browser: keys in JS, public source maps, and data that can be fetched without the backend's permission.
Limit: it only sees what reaches the browserServer-side logic stays unknown. Pair REA with code review and server logs; don't treat a clean REA run as a full audit.
