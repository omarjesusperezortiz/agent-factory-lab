Token Economizer: Microsoft's plugin that learns where your agent wastes tokens

Most token savers build a map of the repo before you start. Microsoft's Token Economizer plugin for Claude Code, Codex and Copilot CLI does the opposite: it watches your sessions in one project and cuts the waste it finds. It remembers mistakes as micro-skills, prunes tools you never call, and nudges the agent when it is stuck. The catch is that it starts out knowing nothing. The running example is AI LABS' demo project, where each message cost about 34,300 tokens.

What this means for us

Token Economizer ideaWhat to do in the factory
Tool definitions are the biggest fixed costGive each agent role an explicit tool allowlist (scout, builder, reviewer) instead of every MCP server. Pruning was the biggest single saving in Microsoft's tests, and our demo lost 29% per message from tools alone.
Repeated failures become project factsLog failed commands per repo in the Traces view. When the same failure shows up in a few sessions, promote it to a line in that repo's CLAUDE.md, with a human approving the change.
Micro-skills read command output as truthKeep auto-learned facts off for any repo we didn't write, and treat distilled facts as untrusted input that needs review before agents see them. This is the prompt-injection path the video warns about.
Pruning is silentShow "tools turned off" next to each run in the console. A run that suddenly "can't" do something should point to toolprune and its restore command first.
Stuck guard nudges once, then asks a humanSame pattern for factory runs: an over-long turn gets a model check, one "try a different hypothesis" nudge, then a Human-inbox item. Never an automatic kill.
Cold start costs more for the first ~6 tasksSeed it from the last 30 days of sessions (the backfill change) before judging it. Measure cost per task over 10+ tasks on the same repo, not one run.
