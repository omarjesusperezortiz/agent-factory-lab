Vercel's CEO on working with agents: seven habits

AI LABS picked seven tips from an interview with Vercel's CEO and turned each one into something you can set up in Claude Code: a /direction command, quality gates, a breaker agent, a first-time-user agent, and MCP-fed triage. One running example throughout: Sitfirst, the furniture-store booking app from the video's terminal, with orders, catalog and chat specs.

What this means for the factory

TipWhat to buildWhere it lives in our factory
1. Test before you commitEvery PRD gets a throwaway MVP run first; an agent verifies claims (model tricks, prompt guides) from scratch.A "spike" stage before the planner hands work to builders.
2. Direction, not volume/direction: one sub-agent per requirement doc, plus a main agent hunting unplanned changes, ending in a scorecard.Evals view: a drift score next to tokens and PRs, so volume never reads as progress.
3. Security and slop debtA security scan after each feature (Vercel's DeepSec, or our own) and a review agent as a gate, strictest on payments and auth.Gate step in every pipeline run; nothing merges until it passes.
4. Must-not trade-offsA "must not trade off" section in CLAUDE.md, where every rule has a committed test.Per-project constraints file, checked by the evals runner.
5. Breaker agentAn agent whose job is to break the app (concurrency, latency, skipped steps) on a copy of the data, run in a find-fix loop.Pre-ship stage; findings land in Issues.
6. See it as a new customerA first-time-user agent that a hook blocks from reading code, plus browser tests of every key flow that write error-free-session results to JSON.Evals: "error-free sessions" as a headline metric.
7. Speed on feedbackGmail and Sentry MCPs feed a triage agent: clear bugs get fixed now, fuzzy ones go to a human. Track time from report to fix.Human inbox for judgment calls; Traces for report-to-fix time.
