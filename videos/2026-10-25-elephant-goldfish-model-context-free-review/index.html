Elephant-Goldfish Model: plans reviewed by agents that never saw your chat

Google's open-source EGM plugin splits planning in two. An Elephant session that knows everything talks the feature through with you and writes the spec. Then Goldfish subagents with zero context tear it apart before any code exists. The running example is the one AI LABS used: a page in their fashion marketplace that shows each seller which sizes sell, which are sold out, and when to restock.

What this means for us

EGM ideaWhat to do in the factory
Goldfish never see the chatMake every reviewer agent start from the spec and the repo only. Never fork the planner's conversation into the reviewer, or it will just agree with itself.
One review subagent fans out to six lensesGive the reviewers an orchestrator subagent that merges their output into one report. The main agent then reads one file instead of six transcripts.
The human owns the decisionsThe report is noisy on purpose. Route it to the Human inbox as a triage list (keep / drop per finding), not as an auto-apply patch.
Bootstrap writes per-folder READMEsREADMEs aren't loaded automatically. Put a short CLAUDE.md (or AGENTS.md) next to each one that points to it, or the contracts will go unread.
Drift report after buildRun it as a scheduled check across the whole repo. It caught real bugs (sold products could be deleted) that a per-feature review would have missed.
Not for small fixesGoogle says it isn't worth it for a change the agent can make in one pass. Gate it on cost-of-failure: big, expensive features only.
Check the generated CLAUDE.mdOn install, Claude wrote from memory that subagents can't start subagents. Current Claude Code can, and the review needs that, so fix the line if it shows up.
