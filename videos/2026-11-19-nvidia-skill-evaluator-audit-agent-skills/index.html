SkillEvaluator: NVIDIA's audit for agent skills, and what its score does and doesn't tell you

A skill an agent writes for you usually works, so its flaws stay hidden: missing sections, risky scripts, a description too long to reach the model. NVIDIA's free SkillEvaluator checks for all of them in three tiers, from fixed rules with no API key up to live runs with and without the skill. Running example: AI LABS' prod-readiness-review skill (load tests, security, logs, front end), grown over many rounds of edits with Claude Code. It scored a B, 82, and reached an A, 95.2 after the fixes.

What this means for us

IdeaWhat to do in the factory
Gate skills like codeRun skillevaluator validate ./skill --tiers 1 (no key) on every skill change, and add it to CI with skillevaluator ci init. Skills that agents edit over many rounds drift the most, because the agent stops rereading the authoring rules.
Description firstStart every skill's description with when to use it, and keep it under 1,024 characters (the spec's limit). Run skillevaluator harness-check to see which agents load the skill and where the description gets cut.
Fewer, sharper skillsEvery installed skill's name and description load into every session. Prune the skills nobody uses, and run Tier 2 to find instructions that repeat across skills.
Triage before fixingSend every finding through a review step (agent plus the Human inbox) before the fix loop starts. A scanner flags patterns, not intent: a security-review skill has to look for secret files, so those warnings stay after a clean fix.
Lift is the real metricThe Tier 1 score measures layout. Whether a skill earns its tokens is the Tier 3 question: the same tasks with and without it, in a sandbox, scored by a separate judge model. Show both numbers on the Evals view, and ask before running Tier 3, since every task costs two agent runs.
Portable scriptsNo absolute paths from one machine and no servers bound to the whole network. Tier 1 catches both, and they break or expose a skill as soon as it's shared.
