The Claude Code team's review system, rebuilt as a loop you can run

Anthropic's Claude Code team wrote up how they review code now that agents write most of it. AI LABS turned the ideas into Claude Code skills: evals written before the build, a REVIEW.md of rules, a builder → verifier → reviewer loop with fresh subagents, a risk triage, and a safety net after release. The running example is one feature from their demo app, fr-11 "Reschedule a visit", followed from spec to rollback.

What this means for us

Idea from the Claude Code teamWhat to do in the factory
Evals before code, approved by a humanA feature can't leave Draft until its eval.md (and mockup, if it has UI) is approved in the Human inbox. A Stop hook keeps the builder from saying "done" until the eval gate script passes. The script decides, not the agent.
The builder never reviews itselfBuilder, verifier and reviewer are separate subagents with fresh context. The reviewer reads the diff and REVIEW.md, never the builder's summary.
One REVIEW.md per repo, imported from CLAUDE.mdIt says what counts as a failure, how serious each kind is, what to ignore, how to test, and ends with Learned rules. The loop proposes a one-line rule when the same finding comes back; a human approves it.
Loops need a stop ruleCap rounds (3 in Anthropic's version, 5 in AI LABS'). After round 1 the reviewer only checks the last fix's diff. Every finding names its class so the fix is applied everywhere. Show the round count and repeat rate on the Costs view.
Rigor scales with blast radiusRun a classifier on every change: low (looks wrong), medium (breaks but nothing lost), high (money, lockout, someone else's data). Low merges on green automated checks, medium needs one person, high needs two. CI workflow files always need a person, and an agent's approval never counts as one.
Reading less is safe only if undoing is fastOne branch per feature, commit every green state, and a fix-a-bug skill that reproduces the bug before reverting. Add a blind first-time-user agent (no code access, throwaway DB) before release.
