Stitch CLI + Claude Code: a design workflow that reviews itself

Google's Stitch now has a CLI, so Claude Code can drive it directly. AI LABS wraps that in a five-step workflow (brief, generate, build, animate) with two review skills that catch what neither tool notices alone. The running example is their space-history scroll site, Escape Velocity.

What this means for us

Pattern from the videoHow to apply it
CLI + skill instead of an always-loaded MCPFor tools we call now and then, prefer a CLI that a skill documents. The skill loads only when needed, so the tool's schema doesn't sit in context every turn.
Skills must land in .claude/skills/After any third-party skill install, check where it was written. If it isn't in .claude/, Claude won't load it unless you name it in the prompt.
Interview into brief.md firstBefore a generative step, have the agent interview us with multiple-choice questions until it has nothing left to ask. Every later prompt then follows one written source, so the outputs stay consistent with each other.
Let the agent generate, check and re-promptGive the agent a generator plus a way to judge its output. Here that took 8 Stitch versions. Slow, but the result is better than one-shot.
Two separate reviewersRun one fidelity check ("does it match the spec, at 1920/1280/768/390?") and one quality check ("is it good, judged against the brief, harshly?"). Each report lists issues worst-first, then Claude fixes them. The visual-explainer verify step (1470px + 400px) is the same idea.
Watch for over-animationClaude adds motion on its own. Every animation needs to earn its place in the story; too many streaking stars made the page hard to watch.
