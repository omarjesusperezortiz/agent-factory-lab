Leon Lin's design loop: references, a target, a numeric bar, and judges that didn't build it

Leon Lin, the author of the trending Taste Skill, says the wording of a design prompt barely matters. What gets an agent to an unusually good page is a process: show it pictures, give it a target, put a number on "good enough", give it time, ban the defaults, build the layout before the motion, give exact feedback, and let a fresh judge score the result. He packed the loop into a skill called cook. One running example below: a landing page for Corvina, a Lisbon wine bar, which is the site cook built in the video.

What this means for us

IdeaWhat to do in the factory
Pictures over adjectivesEvery UI task's issue carries a refs/ folder (9–12 screenshots, or a reference site the agent can screenshot with a browser tool) and a short prompt. A task with no references goes back to the Human inbox before a builder picks it up.
Target before buildAsk for three throwaway HTML mockups on one page first, at desktop and phone widths. A human picks one in the inbox and only then does the real build start. A mockup costs far fewer tokens to change than a built app.
A number, not "make it good"Every UI eval states a bar per dimension (the cook ledger uses layout, photo mood, colour, components, detail density, each out of 10, with 9 as the bar). Show the bar next to the score on the Evals view.
Never trust the self-scoreThe builder's own rating is not a gate. Record it, but gate on a judge that runs in a fresh context, and where we can, on a different model. Track the gap between the two as a calibration offset: it shows how much the builder overrates itself.
Time floor plus budget pacingLong design runs get both a minimum time and a hard cap, and spend the usage window evenly (cook planned for about 20% of a 5-hour window per hour). Always set the cap: cook's default floor for a design build is 8 hours. All questions are asked up front, then the run continues without asking.
Slop as clustersRun a slop detector as one of the judges. It should flag a page when several default patterns appear together, not when a single gradient does, and the ban list should live in one file, not be repeated in every prompt.
Two-phase UI buildsSplit UI issues into "layout, no motion" and "motion" stages, with a human check between them. Motion references are videos, which the agent breaks down frame by frame into timings.
Feedback the agent can act onInbox feedback on UI takes a marked-up screenshot or names an exact property ("headline 64→48px"). If the reviewer can't name the problem, the agent first describes what it built so the reviewer has the words.
