DeepSeek's super agent in Claude Code: one router, many workers

DeepSeek's "super agent" replaces a row of Claude Code tabs with one agent you talk to. It's a router that only talks and hands out work, plus workers that only build. AI LABS rebuilt it as Claude Code agents: tickets with an eval.md, a router that checks results itself, a watchdog for silent failures, and a merger and checker for the end. One running example throughout: their app's v0.2 tickets 001, 002 and 006.

The cast, as AI LABS set it up

AgentModelJob
routerOpus, effort highTalks to you, starts every other agent, checks results against eval.md, sends fixes back to the same worker. Told never to write code: it keeps its tools because teammates inherit the session's tools. DeepSeek runs its router on a lighter model.
watchdogSonnet, effort mediumRuns in the background and compacts at 150k tokens. Every 10 minutes it runs a script that lists stuck, looping, silent or deadlocked agents and tells the router.
worker / teammateSonnetBuilds one ticket in its own git worktree. Writes the contract, results and screenshots into the ticket folder. A Stop hook checks it before it can say "done".
testerSonnetStarted by a worker. Runs every check in eval.md in a real browser (Vercel's agent-browser) and reports PASS/FAIL with evidence. It never fixes anything.
merger → checkerSonnetThe merger brings the worktrees into main and resolves conflicts. The checker tests the merged feature in the browser.
reproducerSonnetWhen something breaks, it replays the steps in the browser and fixes small bugs on its own branch. Otherwise it writes a report.

What this means for us

IdeaWhat to do in the factory
Talking and building are two jobsThe Console session the human talks to should never build. It routes tickets and relays choices. Builders get their own context, so a new message never interrupts them.
Tickets before agentsNo ticket leaves Draft without rd.md (what, what not to touch, decisions made) and eval.md (checks, edge cases, what done means). The board's Runs column (alongside / waits for #) is the scheduler's input.
Only choices reach the humanQuestions from workers show up in the Human inbox as 2–3 options. The router checks "done" against eval.md itself, so the inbox gets choices, not status updates.
Someone watches the quiet onesRun a cheap watchdog on a timer: no output for N minutes, repeated tool calls, or two agents waiting on each other. Each becomes an Issue.
Parallel costs tokensEach worker is its own context window. Track tokens per ticket on the Costs view, and use a smaller model wherever the ticket already spells out the work.
Local dies with the laptopDeepSeek's version runs in the cloud and is reached through team chat and GitHub. A local router needs remote sessions, or the factory needs a hosted runner.
