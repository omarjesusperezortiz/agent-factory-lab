Agent Desktop: computer use that reads the accessibility tree instead of screenshots

Built-in computer use takes a screenshot before and after every click and drives your mouse, so it is slow and you can't use the machine meanwhile. Vercel Labs' agent-desktop reads the list of buttons and fields that apps already publish for screen readers, presses them by reference in the background, and tells the agent whether each press arrived. Running example: AI LABS asked Claude Code to test a study planner app like a brand-new student (sign up, upload a syllabus, record a lecture, sync a calendar). Agent-desktop used about 15M tokens against 18M for built-in computer use, in about the same 15 minutes, and walked more of the real user's steps.

What this means for us

IdeaWhat to do in the factory
Test the steps outside the pageBrowser tools can't see the OS file picker, Chrome's permission prompts or a hand-off to Calendar, and those are where the study-planner run found its bugs. Give the QA agent a desktop tool for those steps, and keep browser automation for everything inside the page.
Two kinds of checkRun functional flows through the accessibility tree (cheaper, and the machine stays usable). Keep a screenshot pass for anything about how the app looks: a button the tree reports as clickable can still sit under a pop-up.
Retry only what's safeCopy agent-desktop's rule into our own tool calls: retry automatically only when the error says the action never landed (error.disposition.retry is safe); otherwise re-read state first. That is what keeps an agent from sending the same email or payment twice.
Parallel testers, visible cursorsEach agent gets its own cursor overlay, so two agents can test two apps at once while a human watches. That fits the Console view: one cursor per running agent.
Snapshot cost in the Costs viewBig apps are read as a --skeleton outline first, then one region. Log snapshot size per step; a long inbox or list is where token use climbs, so test on a small seed account.
Sandbox untrusted runsagent-desktop can run the agent inside a separate macOS VM (newer Macs only), so it can't touch real files. Use it for anything that installs or deletes, and route mouse fallbacks (drag, double-click) to the Human inbox as an approval.
