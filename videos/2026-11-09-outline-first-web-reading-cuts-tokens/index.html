Outline first: how only-cli cuts what Claude Code pays to read the web

Claude Code's built-in web tool turns a whole page (menus, language lists, layout code) into tokens, reads the top, has Haiku summarize the middle and drops the rest. oc (only-cli) hands back a ~500-token numbered outline instead and lets the agent open only the section it needs. In the channel's head-to-head research run it cut tokens by about a fifth, not the "half" in the title.

What this means for us

WhereWhat to doWhy
Research workers in the factoryTry oc open → oc read <n> as the default way a research agent reads a page that has no llms.txt.Web pages stay in the context for the rest of the session; a 500-token outline instead of a 74k-token dump keeps long research sessions sharp.
Docs sitesKeep the built-in web tool for sites that publish llms.txt (Claude Code docs, most dev docs).The video found Claude's own tool already reads those word for word; oc adds nothing there.
WiringInstalling isn't enough: add the one-line instruction to CLAUDE.md/AGENTS.md, or install the Claude Code plugin, which ships the skill.Without it the agent never knows the tool exists and keeps using its own fetcher.
Costs viewBefore rolling out, run one research task both ways and log tokens per run, like the video did (4.9M vs 3.9M).One run each is a hint, not a benchmark; our pages and prompts differ.
LoginsDon't give oc login cookies from work accounts to unattended agents.The cookie is your session: whatever the agent opens, it opens as you.
Answers you can checkPrefer flows where the agent quotes the page text it read, not a summary of it.With oc each reader agent read the real post text; with the web tool much of a long page reaches Claude only as a Haiku summary.
