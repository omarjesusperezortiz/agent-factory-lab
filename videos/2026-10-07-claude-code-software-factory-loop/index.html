A software factory inside your repo, built from one prompt

ZazenCodes asks Claude Code (Opus 5.5, high effort) to build a factory out of a skill, seven sub-agents and some markdown files. A feature goes in, gets a spec, a build, four reviews and a final gate, and lands on main or waits for a human. The running example is his first real job: making the Obsidian course pages on his own site free, so only the videos stay paywalled.

What this means for agent-factory-lab

His factoryWhat we take from it
One session runs /factory and only orchestrates; each sub-agent writes exactly one fileThe console's Traces view can be a plain read of a per-job folder. No database is needed until there are many jobs.
The orchestrator is the only writer of job.json; the dashboard only readsOne writer per state file. That avoids races when several jobs run at once, and the UI never changes state by accident.
MAX_RESUMES = 2, so at most 3 review rounds, then ESCALATEPut a hard cap on every review loop and send the open CHANGES to the Human inbox, instead of looping forever.
Approver escalates money/access, deploy/CI, schema/email/dependencies, and product calls like free vs paidA ready-made rule list for what our Human inbox should catch. Everything else can merge without us.
One git worktree and branch per job, ports 5100 + 10nParallel jobs need their own checkout and their own dev server port, or the reviewers look at each other's pages.
Merges failed because the main checkout was dirty (backlog.md)Files the factory edits on every run must be exempt from its own "clean tree" check. Our daily video job resets its clone for the same reason.

Try it on one repo

  1. Copy BUILD_PROMPT.md from the source folder into Claude Code in a real project, with a strong model and high effort.
  2. Restart the session so it loads the new agents, start the dashboard, and commit the factory first (the skill needs a clean tree).
  3. Run /factory <feature> on something small. Read every file in factory/jobs/<id>/ before you trust the approver.
  4. Only then open a second session and try /factory next in parallel.
